## Plugin Marketplace

### Prerequisites

```bash
# PostgreSQL 15+ (for marketplace database)
brew install postgresql@15  # macOS
sudo apt install postgresql-15  # Ubuntu

# S3-compatible storage (AWS S3, MinIO, or local filesystem)
```

### Setup Marketplace Database

```bash
# 1. Create database
createdb only1mcp_marketplace

# 2. Set environment variable
export DATABASE_URL="postgresql://localhost/only1mcp_marketplace"

# 3. Run migrations (from Rust code)
# Migrations are automatically run on first start
```

### Using Plugin CLI

```bash
# Search for plugins
only1mcp plugin search authentication

# Show plugin details
only1mcp plugin info rate-limiter

# Install a plugin
only1mcp plugin install rate-limiter

# List installed plugins
only1mcp plugin list

# Create a new plugin from template
only1mcp plugin init my-awesome-plugin --template basic

# Test your plugin
cd my-awesome-plugin
cargo test
only1mcp plugin test my-awesome-plugin

# Publish to marketplace
only1mcp plugin publish . --token $MARKETPLACE_TOKEN

# Uninstall a plugin
only1mcp plugin uninstall rate-limiter
```

### Publishing Your First Plugin

```bash
# 1. Initialize plugin
only1mcp plugin init my-plugin --template basic

# 2. Edit plugin.yaml
cd my-plugin
vim plugin.yaml  # Update name, description, author

# 3. Implement plugin logic
vim src/lib.rs

# 4. Add tests
vim src/tests.rs
cargo test

# 5. Publish (dry run first)
only1mcp plugin publish . --dry-run

# 6. Publish for real
export ONLY1MCP_MARKETPLACE_TOKEN="your-token-here"
only1mcp plugin publish .
```

### Plugin Manifest Example

```yaml
# plugin.yaml
name: my-plugin
version: 1.0.0
description: An awesome Only1MCP plugin
author: Your Name <your.email@example.com>
homepage: https://github.com/yourname/my-plugin
repository: https://github.com/yourname/my-plugin
license: MIT

capabilities:
  - request_transform
  - response_transform

dependencies:
  only1mcp: ">=0.7.0"
  tokio: "1.0"

config_schema:
  type: object
  properties:
    enabled:
      type: boolean
      default: true
    threshold:
      type: integer
      minimum: 1
      maximum: 100

keywords:
  - authentication
  - security

compatibility:
  min_only1mcp_version: "0.7.0"
  platforms:
    - linux
    - macos
    - windows
```

## Desktop Application

### Installation

```bash
# Build the Tauri app
cd tauri-app

# Install dependencies
npm install

# Development mode
npm run tauri dev

# Production build
npm run tauri build

# The binary will be in:
# - macOS: tauri-app/src-tauri/target/release/bundle/macos/
# - Windows: tauri-app/src-tauri/target/release/bundle/msi/
# - Linux: tauri-app/src-tauri/target/release/bundle/deb/ or .appimage
```

### Running the Desktop App

1. **Launch the app** (double-click the bundle or run from command line)

2. **Start the proxy:**
   - Click the "Start" button
   - Select your config file (or use default ~/.only1mcp/config.yaml)
   - Proxy starts in background

3. **Monitor metrics:**
   - Real-time RPS (Requests Per Second)
   - Average latency
   - Active connections
   - Error rate
   - Live charts showing trends

4. **Stop the proxy:**
   - Click the "Stop" button
   - Proxy shuts down gracefully

### System Tray

The app includes system tray integration:

- **Start**: Start the proxy
- **Stop**: Stop the proxy
- **Quit**: Exit the application

### Configuration

The app looks for config in:
1. Selected file (via file picker)
2. `~/.only1mcp/config.yaml`
3. `/etc/only1mcp/config.yaml`

## Multi-Cloud Deployment

### Google Cloud Platform (GKE)

```bash
cd deploy/gcp/terraform

# 1. Set variables
cat > terraform.tfvars << EOF
project_id = "your-gcp-project-id"
region = "us-central1"
environment = "production"

# Enable marketplace infrastructure
enable_marketplace = true
db_password = "secure-random-password"

# Cluster configuration
machine_type = "e2-standard-4"
node_count = 3
min_node_count = 2
max_node_count = 10

# Redis configuration
redis_tier = "BASIC"
redis_memory_gb = 1
EOF

# 2. Initialize Terraform
terraform init

# 3. Plan deployment
terraform plan

# 4. Deploy infrastructure
terraform apply

# 5. Get cluster credentials
gcloud container clusters get-credentials production-only1mcp-cluster \
    --region us-central1 --project your-gcp-project-id

# 6. Deploy Only1MCP
kubectl apply -f ../../kubernetes/deployment.yaml

# 7. View outputs
terraform output
```

**Outputs include:**
- GKE cluster endpoint
- Cloud SQL connection name
- Redis host and port
- Static IP address
- Plugins bucket name

### Microsoft Azure (Container Instances)

```bash
cd deploy/azure

# 1. Set variables
RESOURCE_GROUP="only1mcp-rg"
LOCATION="eastus"
APP_NAME="only1mcp"

# 2. Deploy with Azure CLI
az deployment group create \
    --resource-group $RESOURCE_GROUP \
    --template-file deploy.bicep \
    --parameters appName=$APP_NAME location=$LOCATION

# 3. Get public IP
az container show \
    --resource-group $RESOURCE_GROUP \
    --name ${APP_NAME}-containers \
    --query ipAddress.ip \
    --output tsv
```

### DigitalOcean (Kubernetes)

```bash
cd deploy/digitalocean

# 1. Create Kubernetes cluster (via DO console or doctl)
doctl kubernetes cluster create only1mcp-cluster \
    --region nyc1 \
    --node-pool "name=worker-pool;size=s-2vcpu-4gb;count=3"

# 2. Get credentials
doctl kubernetes cluster kubeconfig save only1mcp-cluster

# 3. Deploy Only1MCP
kubectl apply -f deploy.yaml

# 4. Get LoadBalancer IP
kubectl -n only1mcp get service only1mcp
```

## Service Mesh (Istio)

### Prerequisites

```bash
# Install Istio 1.20+
curl -L https://istio.io/downloadIstio | sh -
cd istio-1.20.0
export PATH=$PWD/bin:$PATH

# Install Istio on Kubernetes
istioctl install --set profile=default -y

# Enable sidecar injection for only1mcp namespace
kubectl label namespace only1mcp istio-injection=enabled
```

### Deploy with Istio

```bash
# 1. Deploy Only1MCP
kubectl apply -f deploy/kubernetes/deployment.yaml

# 2. Apply Istio configuration
kubectl apply -f deploy/kubernetes/istio/istio-config.yaml

# 3. Verify installation
kubectl -n only1mcp get virtualservice,destinationrule,gateway

# 4. Test canary deployment
# Send request with header: x-version: v2
curl -H "x-version: v2" http://only1mcp.example.com/health

# 90% of traffic goes to v1, 10% to v2 automatically
curl http://only1mcp.example.com/health  # Random 90/10 split
```

### Features Enabled

**mTLS:**
All pod-to-pod traffic is encrypted automatically

**Canary Deployments:**
- 90% traffic to v1 (stable)
- 10% traffic to v2 (canary)
- Header-based override: `x-version: v2`

**Circuit Breaking:**
- Max connections: 1000
- Outlier detection: 5 consecutive errors = 30s ejection
- Health checks: Automatic recovery

**JWT Authentication:**
- JWT validation via JWKS endpoint
- Exemptions for `/health` and `/metrics`

**Observability:**
- Jaeger tracing (100% sampling)
- Prometheus metrics
- Service graph visualization

## Multi-Cluster Routing

### Configuration

```rust
use only1mcp::multicluster::{MultiClusterConfig, RoutingStrategy, ClusterInfo};

let config = MultiClusterConfig {
    clusters: vec![
        ClusterInfo {
            id: "us-central1".to_string(),
            name: "US Central".to_string(),
            region: "us-central1".to_string(),
            endpoint: "https://us-central1.only1mcp.example.com".to_string(),
            weight: 100,
            capacity: ClusterCapacity {
                total_nodes: 10,
                available_nodes: 8,
                total_cpu_cores: 40,
                available_cpu_cores: 32,
                total_memory_gb: 160,
                available_memory_gb: 128,
            },
            status: ClusterStatus::Healthy,
        },
        ClusterInfo {
            id: "europe-west1".to_string(),
            name: "Europe West".to_string(),
            region: "europe-west1".to_string(),
            endpoint: "https://europe-west1.only1mcp.example.com".to_string(),
            weight: 80,
            capacity: ClusterCapacity {
                total_nodes: 8,
                available_nodes: 7,
                total_cpu_cores: 32,
                available_cpu_cores: 28,
                total_memory_gb: 128,
                available_memory_gb: 112,
            },
            status: ClusterStatus::Healthy,
        },
    ],
    routing_strategy: RoutingStrategy::Geographic,  // or LoadBased, CostOptimized, Weighted
    health_check_interval_secs: 10,
    failover_threshold_errors: 5,
};

let manager = MultiClusterManager::new(config)?;
manager.start_health_checks().await?;

// Route a request
let metadata = RequestMetadata {
    client_ip: Some("203.0.113.45".to_string()),
    client_region: Some("us-central1".to_string()),
    user_id: Some("user-123".to_string()),
    priority: RequestPriority::Normal,
};

let cluster_id = manager.route_request(&metadata).await?;
// Returns: "us-central1" (nearest cluster)
```

### Routing Strategies

**1. Geographic Routing:**
Routes to nearest cluster based on client region
```rust
routing_strategy: RoutingStrategy::Geographic
```

**2. Load-Based Routing:**
Selects cluster with most available capacity
```rust
routing_strategy: RoutingStrategy::LoadBased
```

**3. Cost-Optimized Routing:**
Routes to cheapest region
```rust
routing_strategy: RoutingStrategy::CostOptimized
```

**4. Weighted Routing:**
Custom traffic distribution
```rust
routing_strategy: RoutingStrategy::Weighted
// Uses cluster.weight for distribution
```

**5. Failover:**
Primary → Secondary chains
```rust
routing_strategy: RoutingStrategy::Failover {
    primary: "us-central1".to_string(),
    secondary: vec!["europe-west1".to_string(), "asia-east1".to_string()],
}
```

### Health Tracking

```rust
// Get cluster statistics
let stats = manager.get_cluster_stats().await;

for (cluster_id, stats) in stats {
    println!("{}: {} requests, {:.2}ms avg latency, {} failures",
        cluster_id,
        stats.total_requests,
        stats.avg_latency_ms,
        stats.failed_requests
    );
}
```

### Auto-Degradation

Clusters are automatically marked unhealthy when:
- Failed requests exceed threshold (default: 5)
- Health check fails
- Manual intervention

Unhealthy clusters are:
- Removed from rotation
- Monitored for recovery
- Re-added when healthy threshold is met

## Upgrading from v0.6.0

### Breaking Changes

**None!** v0.7.0 is fully backward compatible with v0.6.0.

### New Dependencies

If using new features, add to your `Cargo.toml`:

```toml
# Plugin marketplace
sqlx = { version = "0.7", features = ["postgres", "runtime-tokio-native-tls"] }
base64 = "0.21"
sha2 = "0.10"

# Desktop app (separate tauri-app/Cargo.toml)
tauri = { version = "1.5", features = ["system-tray", "dialog-all", "fs-all"] }

# Multi-cluster routing
# (Already included in main crate)
```

### Database Migration

If using plugin marketplace:

```bash
# 1. Create database
createdb only1mcp_marketplace

# 2. Set environment variable
export DATABASE_URL="postgresql://localhost/only1mcp_marketplace"

# 3. Migrations run automatically on first use
```

### Configuration Updates

No changes required! Your existing `only1mcp.yaml` works as-is.

**Optional:** Add marketplace configuration:

```yaml
marketplace:
  enabled: true
  database_url: "postgresql://localhost/only1mcp_marketplace"
  storage:
    backend: local  # or s3, gcs
    bucket: "/var/lib/only1mcp/plugins"
    endpoint: "http://localhost:8080/storage"

multi_cluster:
  enabled: false  # Set to true to enable
  clusters: []
  routing_strategy: geographic
```
